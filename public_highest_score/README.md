# Output Run: public_highest_score

This folder contains the artifacts for the `public_highest_score` experiment run. It includes the training/inference notebook, dataset helper code, food-web and Punnett helper data, validation predictions, submission output, and the saved LoRA adapter files.

## Contents

- `pixels_vqa_skel_ta.ipynb`: Notebook used for this run.
- `vqa_dataset.py`: Dataset and preprocessing helper code used by the notebook.
- `food_web_mc_lookup.json`: Food-web multiple-choice lookup helper data; see the [Food-web helper](food_web_helper_explanation.md) explanation.
- `punnett_allele_overrides.csv`: Punnett allele override helper data; see the [Punnett-square helper](punnett_helper_explanation.md) explanation.
- `val_preds_ta.csv`: Validation predictions generated by the run.
- `submission.csv`: Submission file generated by the run.
- `lora_adapter_ta/`: Saved LoRA adapter and tokenizer/processor configuration files.

## Code Summary

- `pixels_vqa_skel_ta.ipynb` is the main starter-aligned SmolVLM notebook. It loads the Pixels-to-Predictions CSVs, imports `vqa_dataset.py`, prepares prompts/images, runs validation, fine-tunes or loads a LoRA adapter, and writes `val_preds_ta.csv` plus `submission.csv`.
- `vqa_dataset.py` contains the reusable training/evaluation pipeline code: starter-style prompt construction, image loading/resizing/augmentation, train/eval collation, batched validation, batched test inference, answer-letter parsing, and symbolic overrides for Punnett-square and food-web questions.

## `vqa_dataset.py` Technical Details

`vqa_dataset.py` holds the code that turns the raw CSV rows and images into model-ready batches. It is separate from the notebook because PyTorch `DataLoader` workers need importable top-level classes and functions for multiprocessing.

Key technical pieces:

- Prompt builder: `build_prompt_ta(...)` creates the starter-style prompt with `<image>`, optional context from lecture/hint, lettered choices, and an answer suffix such as `Answer:`. During training, the prompt stops before the gold answer; the collate step appends the target letter.
- Dataset: `TaScienceVQADataset` reads each CSV row, resolves its image path, loads the image, builds the prompt, and returns `id`, `image`, `prompt`, `num_choices`, and optionally `answer`.
- Image size and memory: images are converted to RGB and resized to a square `img_size`. The notebook sets `IMG_SIZE = 224`; the module default is larger, so Evaluators should rely on the notebook setup value. Resized images are cached with an LRU cache to reduce repeated disk reads, but each DataLoader worker has its own cache, so increasing `NUM_WORKERS` can increase memory use.
- Image augmentation: training can enable `image_augment=True`, which applies random resized crop, small rotation, and light color jitter after the cached resize. Validation/test should keep augmentation off by using `is_train=False` or `image_augment=False`.
- Training collate: `collate_vqa_train(...)` uses right padding, appends the correct answer letter to each prompt, tokenizes text+image together, and masks prompt/padding tokens with `IGNORE_LABEL_ID = -100` so loss is computed only on the answer token.
- Evaluation collate: `collate_vqa_eval(...)` uses left padding for generation, keeps `ids`, `num_choices`, prompts, and optional answers, and prepares only the fields needed by `model.generate(...)`.
- Batched validation: `run_validation_ta_batched(...)` runs `model.generate(...)` with `max_new_tokens=1` and `do_sample=False`, decodes outputs, extracts the choice letter, computes accuracy, and can write `val_preds_ta.csv`.
- Batched test inference: `predict_test_ta_batched(...)` uses the same generation/letter parsing flow and returns the final submission dataframe with `id` and 0-based `answer`.
- Inference overrides: after the model predicts a choice, optional symbolic logic can override eligible predictions using the [Punnett-square helper](punnett_helper_explanation.md) and [Food-web helper](food_web_helper_explanation.md), backed by `punnett_allele_overrides.csv` and `food_web_mc_lookup.json`.

Evaluators usually do not need to edit `vqa_dataset.py` unless they change the prompt format, image preprocessing, augmentation policy, collate behavior, generation/parsing logic, or symbolic override behavior. Most run-specific values should be changed in the notebook setup cell: `IMG_SIZE`, `BATCH_SIZE`, `VAL_BATCH_SIZE`, `NUM_WORKERS`, `TA_ANSWER_SUFFIX`, and `FOOD_WEB_SYMBOLIC`.

## If Evaluators Run The Code

Before running the notebook, check the setup cell in `pixels_vqa_skel_ta.ipynb` and update these paths/settings if needed:

1. `PROJECT_ROOT`: repo location. In Colab this currently points to `/content/drive/My Drive/DL/final`; locally it uses the current working directory.
2. `CSV_DIR`: should point to `repo/pixels-to-predictions/`, where `train.csv`, `val.csv`, and `test.csv` live.
3. `IMAGE_ROOT`: should point to the image directory used by the CSV image paths, currently `repo/pixels-to-predictions/images/images`.
4. `DATA_ROOT`: should point to `repo/data/`, where helper files and `outputs/` live.
5. `PUNNETT_ALLELE_CSV`: should point to `repo/data/punnett_allele_overrides.csv`.
6. `food_web_mc_lookup.json`: should be available at `repo/data/food_web_mc_lookup.json`; `vqa_dataset.py` looks for this path after it is moved to the repo root.
7. `LORA_ADAPTER_FOLDER`: set this to an existing adapter path to run inference from a saved adapter, or leave it as `None` to use `DATA_ROOT / "outputs" / "lora_adapter_ta"`.
8. Training knobs: update `MODEL_ID`, `IMG_SIZE`, `BATCH_SIZE`, `VAL_BATCH_SIZE`, `LR`, `EPOCHS`, `LORA_R`, `LORA_ALPHA`, and `LORA_TARGET_MODULES` only if rerunning or changing the experiment.
9. Prompt/scoring knobs: update `TA_INCLUDE_META`, `TA_ANSWER_SUFFIX`, `INCLUDE_PUNNETT_ALLELE_HINT`, and `FOOD_WEB_SYMBOLIC` only if the scoring/prompt format should change.
10. Hugging Face access: set `HF_TOKEN` or `HUGGING_FACE_HUB_TOKEN` if the model or adapter download requires authentication.
